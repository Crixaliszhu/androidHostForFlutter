# 自研线上质量监控第一阶段设计

本文设计 `AndroidHostForFlutter` 第一阶段自研线上质量监控系统，覆盖：

```text
Java/Kotlin 崩溃
Native crash
ANR
App 启动耗时
页面加载耗时
```

第一阶段目标不是一次性复刻 Sentry，而是先建立可控闭环：

```text
客户端采集 -> 本地落盘 -> 批量上报 -> 服务端聚合 -> 指纹归并 -> 看板告警
```

## 1. 总体架构

```text
quality_monitor_android
  crash_java
  crash_native
  anr
  startup
  page_perf
  breadcrumb
  queue
  uploader
  common
```

客户端模块职责：

```text
crash_java
  捕获 Java/Kotlin 未捕获异常，生成 java_crash 事件。

crash_native
  自行捕获 native 致命信号，生成 native_crash tombstone。

anr
  Watchdog 疑似 ANR + ApplicationExitInfo 系统 ANR 补报。

startup
  拆分冷启动、温启动、热启动和 Flutter 引擎初始化耗时。

page_perf
  采集 Activity/Fragment/Flutter 页面首帧、数据 ready、可交互耗时。

breadcrumb
  记录页面、点击、路由、网络、Pigeon/MethodChannel 调用等现场。

queue
  所有事件先落盘，避免崩溃/ANR/弱网导致丢失。

uploader
  下次启动或后台时批量上传，成功后删除本地文件。
```

服务端模块职责：

```text
ingest-api
  接收事件、校验签名、限流、写入原始日志。

symbol-service
  R8 mapping 反混淆、native so 符号化。

fingerprint-service
  生成崩溃、ANR、性能问题指纹。

metrics-job
  按版本、机型、系统、页面聚合指标。

issue-service
  问题聚合、状态流转、负责人归属。

alert-service
  阈值告警、版本灰度拦截、飞书/企业微信/邮件通知。
```

本地目录建议：

```text

```

队列策略：

```text

性能事件可批量压缩
上传成功后删除
超过保留上限时丢弃最旧事件
```

## 3. Java/Kotlin 崩溃采集

客户端入口：

```kotlin
Thread.setDefaultUncaughtExceptionHandler { thread, throwable ->
    // 生成 java_crash 事件，先同步落盘，再交还原始 handler。
}
```

采集字段：

```text
exceptionClass
exceptionMessage
threadName
stacktrace
allThreadStacks
breadcrumbs
lastActivity
memorySnapshot
device/app/version
```

处理规则：

```text
必须保存原始 UncaughtExceptionHandler
自研 handler 落盘后继续调用原 handler
崩溃现场只做轻量同步写入
不要在崩溃现场做复杂网络请求
下次启动扫描本地队列并上传
```

服务端聚合：

```text
exceptionClass + 栈顶业务帧 + cause 链生成 fingerprint
R8 mapping 还原混淆栈
按 versionCode、设备、系统、页面统计
```

## 4. Native Crash 自采集

Native crash 不能依赖 Java 异常机制，需要在 native 层捕获致命信号。

第一阶段需要覆盖：

```text
SIGSEGV
SIGABRT
SIGBUS
SIGILL
SIGFPE
SIGTRAP
```

### 4.1 客户端初始化

```text
Application.onCreate
  -> System.loadLibrary("quality_native_crash")
  -> nativeInit(tombstoneDir, appInfo)
```

native 初始化动作：

```text
1. 创建 tombstone 目录
2. 初始化备用信号栈 sigaltstack
3. 保存旧 signal handler
4. 使用 sigaction 注册 SA_SIGINFO + SA_ONSTACK handler
5. 预分配崩溃现场需要的固定缓冲区
```

### 4.2 Signal Handler 设计

signal handler 中只能做极少量动作，因为崩溃时进程可能已经处于堆损坏、死锁或栈溢出状态。

允许做：

```text
读取 siginfo_t / ucontext_t
写入预打开或新建的 tombstone 文件
使用 async-signal-safe 系统调用
记录 signal、code、fault address、寄存器、当前线程 backtrace
恢复旧 handler 后重新 raise 信号
```

避免做：

```text
malloc/free
Java/JNI 回调
复杂日志库
加锁
启动普通线程
复杂 C++ 对象构造
网络请求
```

第一阶段 tombstone 内容：

```text
Crash type: native
Signal: SIGSEGV
Code: SEGV_MAPERR
Fault addr
pid / tid / thread name
ABI
App version
Registers
Backtrace
Memory maps
Logcat tail，可选
Java main stack，可选
Breadcrumbs 快照文件路径
```

### 4.3 Backtrace 方案

第一阶段推荐分两档：

```text
基础版
  使用 _Unwind_Backtrace 或 frame pointer 回溯当前线程。

增强版
  崩溃后 fork/clone dumper 子进程，由子进程读取目标进程 maps、寄存器和线程栈。
```

基础版实现快，但多线程和无 frame pointer 场景栈可能不完整。增强版更接近成熟 crash SDK，但复杂度更高。

### 4.4 符号化

客户端 tombstone 里保留：

```text
so path
build-id
pc offset
abi
versionCode
```

服务端保存构建产物：

```text
unstripped .so
mapping.txt
build-id 索引
```

符号化流程：

```text
native_crash tombstone
  -> 按 build-id 找 unstripped so
  -> addr2line / llvm-symbolizer
  -> 生成函数名、文件名、行号
  -> 按 native 栈顶业务帧聚合
```

### 4.5 上传策略

Native crash 发生后进程通常会退出，所以采用：

```text
崩溃现场落盘 tombstone
下次启动扫描 files/quality_monitor/native_crash/
上传成功后删除或标记 uploaded
```

## 5. ANR 采集

复用当前 `anr_monitor` 思路，第一阶段分两路：

```text
watchdog
  主线程 5 秒未响应，采集 main/all threads，作为疑似 ANR。

system_exit_info
  Android 11+ 读取 ApplicationExitInfo.REASON_ANR，作为系统确认 ANR。
```

ANR 事件必须包含：

```text
subject
mainThreadStack
allThreadStacks
systemTrace
currentActivity
lastClickBreadcrumb
lastRouteBreadcrumb
lastPigeonCall
```

服务端聚合：

```text
system_exit_info 作为核心 ANR 指标
watchdog 作为卡死趋势指标
按 main thread 栈顶业务帧生成 fingerprint
锁等待、Binder、IO、CPU 忙等分别打原因标签
```

```text
firstActivity.onResume
firstDraw

```

启动类型：

```text

```

客户端实现：

```text

ViewTreeObserver.OnPreDrawListener 或 Choreographer 捕获首帧
业务首页显式调用 markHomeDataReady()
Flutter 容器监听 first frame 回调
```

上报字段：

```text
startupType
totalDuration
applicationDuration
firstActivityDuration
firstDrawDuration
homeDataReadyDuration
flutterEngineDuration
flutterFirstFrameDuration
```

看板指标：

```text
P50 / P75 / P90 / P95 / P99
版本趋势
机型排行
冷启动慢用户占比
Flutter 引擎初始化耗时分布
```


## 8. Breadcrumb 设计

第一阶段至少记录：

```text
Activity/Fragment 生命周期
Flutter route
用户点击 viewId/actionName
网络请求 URL 模板、耗时、状态码
Pigeon/MethodChannel 调用名、耗时、结果
关键业务动作
内存 trim 事件
```

隐私规则：

```text
不记录输入框文本
URL 参数脱敏
用户 ID 使用 hash 或内部匿名 ID
不采集截图
breadcrumb 数量限制 50 条
```

## 10. 告警策略

第一阶段推荐：

```text
Crash Free Sessions < 99.9% / 1h
Java crash count > 20 / 5min
Native crash count > 5 / 5min
system_exit_info ANR count > 10 / 5min
启动 P95 > 3000ms / 30min
核心页面 interactive P95 > 2000ms / 30min
新版本 crash/anr 较上一版本上涨 100%
```

灰度拦截：

```text
新版本 crash free 明显下降 -> 暂停放量
Native crash 新增高频 fingerprint -> 暂停放量
ANR 影响用户数超过阈值 -> 暂停放量
启动 P95 大幅回退 -> 进入观察
```

## 11. 落地顺序

```text

```

```text
接入启动耗时

```

第 3 周：

```text
实现 native signal handler MVP
生成 native tombstone
下次启动上传 native_crash

```

第 4 周：

```text
完善 fingerprint
接入告警
灰度质量看板

```

